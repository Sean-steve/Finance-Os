## Corrected cross-screen financial invariants

1. **Net worth:** net worth = personal cash + individually recorded physical assets + investment market value + newly transferred earmarked goal savings − debt principal. Existing seeded goal balances are treated as earmarks within the existing cash amounts, not additional assets.
2. **Goal contribution:** a local cash-to-goal transfer of KES X reduces demo cash by X and increases earmarked goal savings by X. Net worth **does not change** simply because money was moved internally.
3. **Goal withdrawal:** reverses the contribution, preserving net worth.
4. **Debt repayment:** an explicitly simulated cash-funded principal payment of KES X reduces both selected personal cash and the demo debt principal by X; net worth **does not change** simply because the liability was serviced.
5. **Asset repricing:** changed values flow to Net Worth, Assets, Financial Health and report exports.
6. **Holding trade:** demo purchases and sales move value between local cash and holdings at the identical displayed synthetic price, not an external exchange.
7. **Income source:** local source creation mirrors the shared planning-income record read by financial health and income reports.
8. **Transaction records:** the recorded transaction ledger is reported as actual *local records*, separately from illustrative monthly spending-plan categories. Recording a transaction does not silently deduct bank cash.
9. **Payment provider, tax and insurance:** no authoritative transaction is inferred from the saved local simulation. No live API credentials.
10. **Integrations:** provider previews never count as verified connections or synced balances.

## Required closure order

**Track A — Foundations and accessibility:** fix route-semantics, labeling, contrast, incorrect financial transfers, original viewer timing; rerun the same full audit. Changes should be reviewed for visual regressions.

**Track B — Top-15 visual corrections:** for every ranked screen, adjust actual HTML/CSS/JS to match the **approved source**, not to an assistant-invented redesign. Preserve functional integrations and use the screenshot comparison artifact after each change.

**Track C — Remaining 44 reference-backed screens:** compare against the actual approved PNG/WebP originals, adjust typography, content hierarchy, visual treatments, controls, layout and responsive behavior; repeat comparison until accepted by reviewer.

**Track D — Complete component and experience certification:** keyboard navigation, focus management, screen-reader labels, form validation, empty/error/loading/success states, confirmations, reversible navigation and data continuity across all linked screens.

**Track E — Missing reference and production hardening:** request original Screen 22; complete production backend/auth/privacy/security integrations in separately controlled engineering milestones.

## Reproduce audit locally

Install Node 22+, Python 3.12+, Chromium Playwright, axe-core and Pillow, then:

    npm install --no-save playwright@1.56.1 axe-core@4.10.3
    npx playwright install chromium
    python -m pip install pillow
    node tests/full-reconciliation-qa.cjs
    node tests/cross-screen-integration-qa.cjs
    python scripts/visual-reconciliation-metrics.py

Audit output folder: qa-artifacts/full-reconciliation.

The full visual audit creates **evidence**, not automatic certification. Certification requires a reviewer-approved visual and functional sign-off for the available source-backed screens.
